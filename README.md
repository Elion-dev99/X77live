# X77live オンライン稼働管理 Bot

大阪店LIVE在籍メンバーの**オンライン稼働状況**を追跡し、Discord チャンネルに **10分ごと**（カスタマイズ可）の定期通知を送る Bot です。

## できること

| 機能 | 説明 |
|------|------|
| **オンライン開始/終了** | メンバーが `/オンライン開始` `/オンライン終了` で稼働状況を報告 |
| **稼働状況一覧** | `/状況` で誰がオンライン中か・未稼働かを一覧表示 |
| **定期通知** | 設定した間隔（デフォルト10分）で通知チャンネルに Embed 送信 |
| **在籍管理** | メンバー登録・削除、ロール同期で大阪店在籍者を管理 |
| **細かいカスタマイズ** | 通知間隔・表示項目・並び順・通知停止時間帯など `/設定` で変更 |

## コマンド一覧

### メンバー向け

| コマンド | 説明 |
|----------|------|
| `/オンライン開始` | オンライン稼働を開始（メモ付き可） |
| `/オンライン終了` | オンライン稼働を終了 |
| `/状況` | 現在の稼働状況 |
| `/在籍一覧` | 在籍メンバー一覧 |
| `/履歴` | 最近の開始/終了履歴 |
| `/ヘルプ` | コマンド一覧 |

### 管理者向け

| コマンド | 説明 |
|----------|------|
| `/メンバー登録` | 在籍メンバーを追加 |
| `/メンバー削除` | 在籍メンバーを削除 |
| `/ロール同期` | 在籍ロールのメンバーを一括登録 |
| `/設定` | 通知間隔・チャンネル・表示項目等を変更 |
| `/設定確認` | 現在の設定を表示 |
| `/通知テスト` | 定期通知のプレビュー送信 |
| `/強制終了` | 指定メンバーのオンラインを強制終了 |

## カスタマイズ項目（`/設定`）

| 項目 | 説明 | 例 |
|------|------|-----|
| 店舗名 | 通知タイトルに表示 | `大阪店` |
| 通知チャンネル | 定期通知の送信先 | `1234567890` |
| 通知間隔（分） | 定期通知の間隔 | `10` |
| 定期通知 ON/OFF | 定期通知の有効/無効 | `true` / `false` |
| 在籍ロール | このロールを持つ人を自動登録 | `<@&ロールID>` |
| メンションロール | 定期通知時にメンション | `<@&ロールID>` |
| 稼働時間表示 | オンライン開始からの経過時間 | `true` |
| オンライン一覧表示 | 定期通知にオンライン中一覧 | `true` |
| 未稼働一覧表示 | 定期通知に未稼働一覧 | `true` |
| 通知停止開始/終了時刻 | 指定時間帯は通知しない | `02:00` / `06:00` |
| フッターテキスト | Embed フッター | `X77live` |
| オンライン/未稼働並び順 | `name` / `duration` / `recent` | `name` |

## セットアップ

### 1. Discord Developer Portal

1. [Discord Developer Portal](https://discord.com/developers/applications) で Application を作成
2. **Bot** → Token を控える
3. **Privileged Gateway Intents** で **SERVER MEMBERS INTENT** を ON
4. Application ID（Client ID）を控える

### 2. ローカル開発

```bash
npm install
cp .env.example .env
# .env に DISCORD_TOKEN, DISCORD_CLIENT_ID, DISCORD_GUILD_ID を設定
npm start
```

### 3. Railway デプロイ

1. [Railway](https://railway.com/) で GitHub リポジトリを Import
2. **Variables** に以下を設定:

| 変数名 | 必須 | 説明 |
|--------|------|------|
| `DISCORD_TOKEN` | ✅ | Bot トークン |
| `DISCORD_CLIENT_ID` | ✅ | Application ID |
| `DISCORD_GUILD_ID` | 推奨 | サーバー ID（スラッシュ即時反映） |
| `NOTIFY_CHANNEL_ID` | 推奨 | 通知先チャンネル ID |
| `NOTIFY_INTERVAL_MINUTES` | 任意 | 通知間隔（デフォルト 10） |
| `STORE_NAME` | 任意 | 店舗名（デフォルト 大阪店） |
| `MEMBER_ROLE_ID` | 任意 | 在籍ロール ID |
| `DATA_DIR` | 任意 | Volume マウント時 `/data` |

3. **Volume** を追加し、マウントパス `/data` に設定（データ永続化）
4. Deploy 成功後、Discord で `/ヘルプ` を試す

### Bot 招待

```bash
npm run invite
```

## 運用フロー

```
1. 管理者が /メンバー登録 または /ロール同期 で在籍メンバーを登録
2. 管理者が /設定 で通知チャンネル・間隔等を設定
3. メンバーが出勤時に /オンライン開始、退勤時に /オンライン終了
4. Bot が 10分ごとに通知チャンネルへ稼働状況を Embed 送信
```

```
🟢 オンライン中 (3)
  太郎 (1時間23分)
  花子 (45分) — 配信A
  次郎 (12分)

⚪ 未稼働 (2)
  四郎
  五郎
```

## 開発

```bash
npm test              # ユニットテスト
npm run dev           # ファイル変更で自動再起動
npm run register-commands  # スラッシュコマンド手動登録
```

データは `data/config.json`（または Railway Volume の `/data/config.json`）に保存されます。

## トラブルシューティング

| 症状 | 対処 |
|------|------|
| Bot が起動しない | Railway Logs で `DISCORD_TOKEN` エラーを確認 |
| コマンドが表示されない | `DISCORD_GUILD_ID` を設定して再デプロイ |
| 定期通知が来ない | `/設定確認` で通知チャンネル・有効状態を確認 |
| データが消えた | Railway Volume を `/data` にマウントし `DATA_DIR=/data` を設定 |
